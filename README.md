# promo-channels

开源项目的推广渠道清单。在哪投、怎么投、有什么门槛，投过什么。

每次都重新查一遍太浪费：哪个 awesome 列表收 PR、哪个卡 star 数、哪个站点的收录规则藏在 contributing 的第 80 行。查完就忘，下次再来一遍。攒在这里。

## 怎么用

**目录类优先。** 它们长期被搜到，投一次管很久；社区帖两天就沉。star 的增长大头来自"被人搜到"，不是来自"被人看到一次"。

**社区帖配合窗口期。** 发布当天、版本更新、或者蹭一个外部热点。发完就结束，别指望它持续带量。

**投完在 [LOG.md](LOG.md) 记一行。** 半个月后你不记得投过哪几家，重复投稿会让维护者觉得你在广撒网。

## 几条通用规律

**门槛藏在细节里。** 同样叫 awesome 列表，有的只要一个 YAML 文件且 CI 全自动校验，有的要求 star 数过 10，有的要求仓库创建满一天。不读 contributing 直接提，大概率红叉。

**自动抓取不可靠。** 有些目录声称按 GitHub topic 自动收录，实际上不一定会抓到你——加了 topic 和 description 之后照样几个月没进去。该主动提的还是要提。

**投稿 ≠ 涨 star。** 列表带来的是一次曝光加一条永久外链，真正转化要看项目首页写得怎么样。先确保 README 在手机上和 npm 上都能正常打开。

**别一天投十家。** 维护者会看 PR 历史。分散到几天，每家单独读一遍他们的格式要求。
